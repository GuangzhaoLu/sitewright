# Amazon · 往后写与两张披萨

公开来源：[Working Backwards 对 PR/FAQ 的说明](https://workingbackwards.com/concepts/working-backwards-pr-faq-process/)、AWS 对 [two-pizza teams](https://d1.awsstatic.com/executive-insights/en_US/two_pizza_teams_eBook.pdf) 的概述、SHRM 对 Day 1 / Working Backwards 的介绍。

## 他们实际在做什么

1. **先定义顾客体验，再倒推要造什么。** 工具是一页新闻稿 + FAQ（PR/FAQ）。写到能让未参与的人读完就懂：为谁、解决什么、第一天怎么开始用、做起来有多贵多难。
2. **叙事会改十几稿。** 开会先默读，职级高的后发言，避免一开口就定调。目的不是「获得同意」，是打磨想法、找出漏洞。
3. **两张披萨的小队**对**一个**服务和它的用户负全责（single-threaded ownership），做完不扔给别人运维。跨团队靠接口，不靠把人混在一个大组里。
4. 日常还用书面叙事做运营复盘，而不是只有幻灯片。

## 网页小站能用的

| 拿走 | Sitewright 里的落点 |
|---|---|
| 先写体验再开工 | S0：`00-BRIEF.md`，对外时加 `02-PRFAQ.md` |
| 写到能被打叉 | 简报必须有「成功长什么样」和「禁止」 |
| 小队吃得饱就停 | 同时上场人数有上限；不拆微服务 |
| 单线程 | 一个指挥收口；进度只一个全局对象 |

## 不要用的

- 把 FAQ 写成内部政治文件。
- 为「像 Amazon」而强制六页英文。
- 把每个页面当成独立两张披萨团队——一个静态站只有一个产品面。
