# 游戏工作室 · 从设定到过审

通例来自制作流程（概念 → GDD → 预制作竖切片 → 量产 → Alpha/Beta → 过审 QA → 上线），不是某一家的保密管线。GDC 上反复出现的角色：制作人、系统策划、关卡、叙事、美术指导、概念、2D/3D、动画、程序、音效、QA、UX。

## 他们实际在做什么

1. **GDD 先冻核心循环**，再铺关卡和美术。中途改核心循环等于重做。
2. **竖切片（vertical slice）**：先打通「能代表成品品质」的一小段，再复制。切片不及格就不要量产。
3. **美术圣经 / 风格帧**先于量产图，避免每人画一种世界。
4. **失败也是设计**：教玩家，而不是只扣分。严肃游戏还要写清楚「什么不算赢」。
5. QA 分功能、兼容、认证。认证测试的心态：对照清单，不对照感觉。
6. MDA（Hunicke 等）：机制 → 动态 → 审美。先定玩家应感到什么，再选机制。

网页小游戏不是主机发行，但「先冻循环、先打通一局、清单验收」完全适用。

## 网页小站能用的

| 拿走 | Sitewright 里的落点 |
|---|---|
| GDD | `01-GAMES.md` |
| 制作人平行催场 | 指挥；禁止策划自己写上线 JS |
| 竖切片 | S4 |
| 风格帧 | 视觉备忘 + 插图提示词 |
| 「什么不算赢」 | 每一局写死陷阱 |
| 过审清单 | `out/qa-checklist.md`（空表在 `templates/qa-checklist.md`） |

## 不要用的

- 战斗数值、抽卡、体力。
- 把简报禁止的操作步骤做成可玩游戏。那是项目简报里的禁止项，不是通用规格。
