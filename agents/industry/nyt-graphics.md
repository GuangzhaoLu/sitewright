# 《纽约时报》图形组 · 互动网页怎么出片

公开来源：图形编辑访谈与流程复盘（如 American Press Institute 对 Times 解释性图形的报道、公开讲座里的工作步骤）。Times 图形组把数据记者、设计、程序、编辑放在同一张桌子上，做从一小时条形图到数周 scrollytelling 的活。

## 他们实际在做什么（压缩成 Sitewright 能跑的）

1. 选题 / 提案  
2. 找数据与事实  
3. 探索：这图是不是故事本身  
4. 手绘草稿  
5. **原型**（D3 / HTML，丑但能点）  
6. 内部评议  
7. 迭代  
8. 事实核对  
9. **读稿 / copy edit**  
10. 发布  
11. 上线后看它烂不烂  

内容常用结构化稿（他们内部有 ArchieML 一类：记者在文档里写结构，程序吃结构而不是吃设计稿）。打印走 Illustrator，网上走 HTML/JS。决策经常是：这条该上照片、上图，还是上互动。

代表作量级：*Snow Fall*、*You Draw It*——都是「先选一种互动，再喂内容」，不是先堆专题再找玩法。

## 网页小站能用的

| 拿走 | Sitewright 里的落点 |
|---|---|
| 记者×设计×程序同桌 | 内容 JSON + 玩法 JS 分开，合同字段冻结 |
| 先原型 | S4 竖切片 |
| 读稿台 | S6 QA，事实与分层错误当 P0 |
| 结构稿 | `data/play-*.json`，不把题写死在 JS 里 |
| 「这该不该做成互动」 | Librarian：能静帧讲清就不要视频或游戏 |

## 不要用的

- Kafka 发布管道、全站 CMS。
- 为每个页面上 D3。默认原生 HTML/CSS/JS。
