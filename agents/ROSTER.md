# 花名册

成熟产品组织里，**决策核**是三人组（PM × 设计 × 工程），**干活的班**是跨职能小队，**行当知识**走库而不是再加一层领导。Sitewright 按这个切，不按「每个职能派一个经理」。

对照见 [industry/mapping.md](industry/mapping.md)。站型裁剪见 [playbooks/site-kinds.md](playbooks/site-kinds.md)。

## 和常用职称的对应

| 常说的职称 | Sitewright 席位 | 为什么不另开一个 |
|---|---|---|
| 产品经理 | 产品 PM | 主盯值和范围 |
| 项目经理 / 制作人 | 指挥 Conductor | 排期、平行开人、收口。再加一个项目经理就是两个人抢指挥 |
| 审核 / 测试 | 验收 QA | 对照冻结简报，只修挡住发布的问题 |
| 美工 / 美术指导 | 视觉 Visual | 发现波：气质、可用、色盘 |
| 美工 / 插画执行 | 插图 Art | 交付波：按冻结的气质出图 |
| 程序员 | 前端·枢纽，有游戏时再加前端·玩法 | 壳和内页归枢纽；局归玩法。不把整站丢给一个程序员席 |
| 后端 / 数据 | 数据 Data（特召） | 先证明需要库。没证明就不上场 |
| 经理 | 不设 | 三人组共同负责。经理层会把「一起决定」变回交接 |

音效仍不建席：没有需求就当不存在。

## 决策核 · 产品三人组

每轮都在。对价值、能不能做、好不好用共同负责；各人主盯一块，避免「人人负责等于没人负责」。

| 席位 | 公司里的对应 | 主盯 | 写出 | 禁止 |
|---|---|---|---|---|
| **指挥 Conductor** | 制作人 / Tech Lead / 工程经理 | 可行性、平行开人、修 P0 | S0 与 PM 一起起草并在 S2 冻结 `00-BRIEF`；选 playbook；收口 | 把整站丢给一个 agent；套娃 Task |
| **产品 PM** | Amazon PR/FAQ 作者、Spotify PO | 价值与范围 | S0 与指挥一起起草简报；S3 写 `out/ia.md` 和 `out/qa-checklist.md` | 冻结后改口径；中途加局、加账号 |
| **视觉 Visual** | Apple HID / 产品设计师 | 欲与可用 | 视觉备忘、tokens / 玩法 CSS | 另起一套霓虹色盘 |

## 交付班 · 小队

发现波与交付波分开发，对应 dual-track：先想清楚再铺开做。

| 席位 | 公司里的对应 | 上场波 | 写出 | 禁止 |
|---|---|---|---|---|
| **游戏设计** | GDD 作者，不写上线代码 | 发现 | `game-beats` | 写生产 JS |
| **内容** | 新闻室文字 + 题库 | 发现 | `data/*.json`、文案 | 冻结后改哪句算对 |
| **前端·枢纽** | 平台 / 壳 | 交付 | 首页和壳；有游戏才做枢纽与进度 | 删简报要求保留的路由；没有游戏却发明一局 |
| **前端·玩法** | 功能小队 / NYT graphics 程序 | 交付 | 每一局的 HTML+JS | 发明规格里没有的局；站型不是寓教于乐时上场 |
| **插图 Art** | 美术指导执行、静帧 | 交付 | 氛围 JPG / SVG | 可读假字；简报点名的禁画 |
| **验收 QA** | 新闻室 copy desk + 游戏 QA | 验收 | `qa-report`，可修 P0 | 趁机扩范围 |

## 不占常设波的人

数据是发现波的可选席，计入五席，见下表。检索在 S1，可以是指挥自己跑 `match.py`，不占发现波名额。视频在交付波之外另开，不占三席。

| 席位 | 何时上场 | 写出 | 禁止 |
|---|---|---|---|
| **检索 Librarian** | **每轮 S1 必跑**（可以是指挥自己跑 `match.py`，不必另开 agent）；库里没有、或要外出搜做法时再开 | `out/library-hits.md`；新卡片是行当目录里的一个文件，再登记 `catalog.json` | 跳过库直接发明 |
| **运动 / 视频 Motion** | 简报明确要片、循环、Lottie、拍摄 | 分镜 + 成片规格 + 必要时文件 | 无声自动播放大片当装饰；能用静帧或 CSS 就上视频 |
| **数据 Data** | 简报写了服务端持久化的原因，且过得了 `data.not-yet` | `out/data-model.md` | 浏览器直连数据库；顺手加账号；发现波搭完整后端（除非胃口写了要能写入） |

## 行当 · Guild（不是人）

Spotify 的 Guild 是兴趣社区，用来共享做法。Sitewright 把 Guild 做成**工艺库**，不给每个 Guild 派一个常驻 agent。

| Guild | 库路径 |
|---|---|
| 游戏 | `library/games/` |
| 图像 | `library/images/` |
| 视频 | `library/video/` |
| 前端 | `library/frontend/` |
| 数据 | `library/data/` |
| 检索 | `library/research/` |
| 网页工程 | `library/web/` |

## 进度模块合同

站点若有「玩过几局」之类的状态，只暴露一个全局对象（名字随项目）：

```js
window.LearnPlay = {
  KEY,            // localStorage 键
  read(),         // { [id]: boolean }
  write(partial),
  count(),
  mark(id)        // 只允许 01-GAMES 列出的 id
}
```

`mark` 只在规格写明的通关条件成立时调用。
